\chapter{METODE DAN RANCANGAN PENELITIAN}

\section{Rancangan Penelitian}

Penelitian ini menggunakan rancangan \textit{eksperimen terkontrol berpasangan} (\textit{paired controlled experiment}). Unit analisisnya adalah satu percobaan agent pada satu task perbaikan bug. Setiap task dijalankan pada snapshot kode, prompt, model, agent runner, dependency, dan batas resource yang sama. Perbedaan antar-kondisi hanya terletak pada feedback test yang diterima agent.

Rancangan ini dipilih untuk menjawab pertanyaan kausal secara terbatas: apakah feedback yang tidak stabil mengubah outcome dan perilaku agent ketika faktor lain dibuat tetap? Hasil penelitian diinterpretasikan sebagai bukti pada kombinasi benchmark, task, agent, model, dan environment yang diuji, bukan sebagai ukuran universal kemampuan semua AI coding agent.

\section{Objek dan Unit Analisis}

Objek penelitian adalah proses perbaikan bug menggunakan AI coding agent. Satu unit analisis didefinisikan sebagai pasangan:

\begin{enumerate}[leftmargin=*]
    \item satu task perbaikan bug pada snapshot repository tertentu; dan
    \item satu eksekusi agent pada salah satu kondisi feedback yang ditetapkan.
\end{enumerate}

Target awal untuk tahap pilot adalah tiga task dengan sekurang-kurangnya tiga pengulangan pada setiap kondisi. Apabila pilot berhasil, eksperimen utama menargetkan sekurang-kurangnya sepuluh task dengan sekurang-kurangnya tiga pengulangan per kondisi. Jumlah akhir dapat disesuaikan berdasarkan biaya, tetapi seluruh perubahan jumlah task dan pengulangan dicatat sebelum eksperimen utama.

\section{Pemilihan Benchmark dan Task}

Defects4J dipilih sebagai kandidat benchmark utama karena menyediakan bug nyata, test suite, dan infrastruktur untuk eksperimen terkontrol \cite{defects4j2014}. Benchmark APR lain dapat dipertimbangkan apabila bahasa pemrograman, build system, atau kebutuhan resource Defects4J tidak kompatibel dengan agent yang tersedia.

Task yang dapat digunakan harus memenuhi kriteria berikut:

\begin{enumerate}[leftmargin=*]
    \item snapshot commit dapat diambil dan dibangun tanpa secret atau layanan eksternal yang tidak tersedia;
    \item terdapat failing test atau acceptance test yang dapat memandu proses perbaikan;
    \item command build dan test dapat dicatat secara eksplisit;
    \item hasil baseline sebelum agent berjalan dapat direproduksi;
    \item tersedia validation oracle untuk memeriksa hasil akhir secara independen; dan
    \item waktu eksekusi dan kebutuhan resource masih sesuai dengan batas eksperimen.
\end{enumerate}

Sebelum task digunakan, test dijalankan berulang pada environment yang sama untuk memeriksa baseline. Task yang menunjukkan ketidakstabilan sebelum perlakuan diberikan tidak digunakan sebagai task utama, karena dapat mencampurkan flaky feedback alami dengan flakiness yang sengaja diinduksi.

\section{Konstruksi Perlakuan Feedback}

Perlakuan diimplementasikan melalui feedback wrapper yang memisahkan hasil test sebenarnya dari hasil yang dilaporkan kepada agent. Wrapper menyimpan dua nilai: \textit{true result}, yaitu hasil eksekusi test tanpa manipulasi, dan \textit{reported result}, yaitu hasil yang diterima agent. Perbedaan antara kedua nilai tersebut memungkinkan integritas perlakuan dan kebenaran patch diperiksa secara terpisah.

Pada perlakuan utama, wrapper menggunakan intermittent false failure. Ketika test yang mendasari sebenarnya lulus setelah patch diterapkan, wrapper dapat melaporkan kegagalan dengan probabilitas tertentu. Kegagalan yang memang terjadi sebelum patch tidak diubah, sehingga agent tetap menerima sinyal bug awal yang benar. Probabilitas, seed, timestamp, command, output asli, dan output yang dilaporkan disimpan dalam manifest.

False pass dan unstable timeout dapat ditambahkan sebagai analisis sensitivitas setelah perlakuan utama terbukti dapat direproduksi. Penambahan skenario tersebut tidak dilakukan secara otomatis karena masing-masing mempunyai ancaman validitas dan mekanisme dampak yang berbeda.

\section{Protokol Eksperimen}

Protokol eksperimen untuk setiap task adalah sebagai berikut:

\begin{enumerate}[leftmargin=*]
    \item mengambil snapshot repository dan dependency yang telah dipatok;
    \item memeriksa baseline test dan menyimpan outputnya;
    \item membuat workspace baru untuk setiap run agar perubahan dari run sebelumnya tidak terbawa;
    \item menjalankan agent dengan prompt, tools, model, dan batas resource yang sama;
    \item mengarahkan command test melalui wrapper sesuai kondisi eksperimen;
    \item menyimpan trajectory, patch, true test result, reported test result, token, tool calls, retry, dan wall-clock time;
    \item menghentikan agent ketika patch diterima, batas iterasi tercapai, batas waktu habis, atau agent gagal melanjutkan;
    \item menjalankan validation oracle independen tanpa manipulasi feedback; dan
    \item mengarsipkan hasil dengan identifier task, kondisi, seed, versi runner, dan timestamp.
\end{enumerate}

Urutan kondisi diacak per task untuk mengurangi efek urutan. Setiap run harus menggunakan workspace yang bersih. Run yang melewati wrapper atau mengubah konfigurasi perlakuan dinyatakan tidak valid dan dilaporkan, bukan diam-diam digabungkan dengan hasil utama.

\section{Pengumpulan Data}

Setiap run menghasilkan artefak berikut:

\begin{enumerate}[leftmargin=*]
    \item manifest yang berisi task, commit, kondisi, seed, model, runner, dependency, dan batas resource;
    \item prompt awal dan konfigurasi tools;
    \item trajectory action-result agent;
    \item patch akhir dan diff seluruh perubahan;
    \item raw test output, true result, reported result, dan catatan rerun;
    \item jumlah token input dan output jika disediakan runner;
    \item jumlah tool calls, feedback iterations, retry, dan durasi; serta
    \item hasil validation oracle dan keputusan patch correctness.
\end{enumerate}

Data yang mengandung credential, secret, atau informasi privat tidak digunakan. Repository dan task yang dipilih harus mempunyai lisensi yang mengizinkan penggunaan untuk eksperimen dan publikasi artefak yang relevan.

\section{Analisis Data}

Analisis dilakukan dalam empat tahap:

\begin{enumerate}[leftmargin=*]
    \item \textbf{Pemeriksaan integritas.} Memastikan true result, reported result, seed, wrapper log, dan validation result konsisten.
    \item \textbf{Analisis outcome.} Membandingkan repair success, patch plausibility, dan patch correctness pada kondisi yang sama. Jika jumlah task mencukupi, uji berpasangan untuk outcome biner digunakan; jika tidak, perbedaan proporsi, interval kepercayaan, dan contoh per task dilaporkan.
    \item \textbf{Analisis biaya.} Membandingkan median, sebaran, dan paired difference untuk token, tool calls, retry, iterations, dan waktu. Uji Wilcoxon atau permutation test dapat digunakan apabila asumsi dan ukuran sampel memadai.
    \item \textbf{Analisis failure mode.} Mengelompokkan trajectory ke dalam kategori seperti unnecessary edit, repeated retry, premature stop, false diagnosis, timeout exhaustion, dan successful recovery. Contoh trajectory digunakan untuk menjelaskan mekanisme di balik perbedaan angka.
\end{enumerate}

Efek utama dirangkum dengan perbedaan antara kondisi, misalnya:

\begin{equation}
\Delta_{flaky} = Outcome_{deterministic} - Outcome_{flaky}
\end{equation}

dan:

\begin{equation}
\Delta_{recovery} = Outcome_{stability\text{-}aware} - Outcome_{flaky}.
\end{equation}

Nilai delta tidak ditafsirkan tanpa melihat interval ketidakpastian, jumlah task, dan distribusi per task. Hasil negatif atau tidak signifikan tetap dilaporkan karena menunjukkan bahwa dampak flakiness tidak konsisten pada konfigurasi yang diuji.

\section{Alat dan Bahan}

Alat dan bahan yang dipersiapkan adalah sebagai berikut:

\begin{enumerate}[leftmargin=*]
    \item \textbf{Agent runner:} satu CLI atau framework agent yang dapat membaca repository, menjalankan command, mengubah file, dan menyimpan trajectory. Runner final dikunci setelah pilot.
    \item \textbf{Model:} satu model dasar yang aksesnya stabil dan dapat digunakan berulang dengan batas anggaran yang ditentukan. Perbandingan banyak model bukan tujuan utama.
    \item \textbf{Benchmark:} Defects4J sebagai kandidat utama dan benchmark APR lain sebagai fallback apabila diperlukan.
    \item \textbf{Feedback wrapper:} program yang meneruskan command test, menginduksi reported result sesuai seed, dan merekam true result serta reported result.
    \item \textbf{Environment:} Git, Docker atau isolasi setara, runtime bahasa yang sesuai benchmark, dan penyimpanan log.
    \item \textbf{Validation tools:} command test asli, test tambahan atau hidden test bila tersedia, serta pemeriksaan manual pada subset patch.
\end{enumerate}

Versi tool, model identifier, command, dan konfigurasi lingkungan disimpan dalam manifest. Model atau layanan berbayar tidak digunakan pada eksperimen utama sebelum smoke test satu task berhasil dan biaya maksimum per run ditetapkan.

\section{Kriteria Go/No-Go}

Eksperimen utama dilanjutkan apabila seluruh syarat berikut terpenuhi:

\begin{enumerate}[leftmargin=*]
    \item baseline task dapat dibangun dan dijalankan berulang;
    \item wrapper dapat memisahkan true result dan reported result;
    \item intermittent false failure dapat diulang dengan seed yang sama;
    \item runner dapat merekam patch, trajectory, output test, token atau proxy cost, tool calls, dan waktu; serta
    \item validation oracle dapat membedakan patch plausibility dari patch correctness.
\end{enumerate}

Jika syarat utama belum terpenuhi, penelitian dipersempit menjadi satu benchmark, satu pola intermittent false failure, dan satu bentuk stability check. Jika agent tidak dapat diarahkan melalui wrapper secara konsisten, eksperimen agentic diposisikan sebagai tidak valid dan desain dievaluasi kembali sebelum pengumpulan data utama.
